# Lightfolio 开发记录

## 项目定位

Lightfolio 是一个面向个人摄影作品管理与浏览的本地电子相册应用。
当前技术栈为 Electron + React + TypeScript，采用 monorepo 结构拆分为 app、core、shared 三层。

## 当前已完成

### 工程与构建

- 完成 workspace 架构整理，根目录可统一执行 typecheck 与 build。
- 修复 core/shared 在 ESM 运行时的导出路径问题。
- 修复 app 的 Electron 入口路径与 preload 入口路径。

### 导入链路

- 已支持选择单张或多张图片/视频文件导入。
- 已支持选择目录后递归扫描图片/视频文件。
- 已加入导入去重逻辑，避免同一文件重复进入时间轴。

### 元数据

- 已接入 EXIF 读取基础能力。
- 拍摄时间采用回退策略：EXIF 时间 -> 文件修改时间 -> 导入时间。

### 界面与交互

- 已有时间轴、精选画册、详情面板三块核心界面。
- 已支持从相册移除资源，不删除磁盘原文件。
- 已支持恢复已移除资源。
- 已支持将磁盘文件移动到系统回收站。

## 当前已知问题

- 资源卡片仍是占位视觉，未显示真实缩略图。
- 导入结果尚未持久化，应用重启后不会保留。
- 导入失败或桥接异常时，前端反馈仍不够明显。
- Windows 下运行时存在 cache 目录权限告警，但当前不阻塞主功能。

## 下一阶段建议

### 第一优先级

- 增加导入成功/失败的显式提示。
- 增加真实缩略图展示能力。
- 增加基础持久化，让导入结果在重启后可恢复。

### 第二优先级

- 拆分 App 页面组件，降低单文件复杂度。
- 加入标签、说明、地点编辑能力。
- 增加搜索与筛选。

### 第三优先级

- 设计 AI Provider 抽象接口。
- 预留人像、风景等自动分类能力。
- 支持人工覆盖 AI 分类结果。

## 设计原则

- 不移动、不复制、不隐式修改用户磁盘中的原始素材。
- “从相册移除”仅影响 Lightfolio 内部视图，不影响原文件。
- “删除磁盘文件”必须是显式危险操作，并走系统回收站。
- 数据层优先保存索引、标签、说明、隐藏状态等元信息，而不是保存素材本体。
